# Repository repair and field UI alignment

## Confirmed before this change

- The default `main` branch contains only the introductory README. The existing application is on `foundation/existing-app`, with draft PR #2 proposing its import. This repair does not merge that import or replace main.
- GitHub run 39160806278 installs with npm 10.8.2 / Node 20.20.2. Each install logs `Exit handler never called!` but is reported successful. The build then fails with `vite: not found`, tests cannot load esbuild or Jest, and type checking can fall back to a different global compiler.
- The root lockfile contains 679 download references to `package-firewall.replit.internal`, an environment-specific Replit registry address. Those references are not portable to a GitHub-hosted runner.
- The locked `@whatwg-node/disposablestack` and `@whatwg-node/promise-helpers` require Node 22.15 or later, while CI selected Node 20.
- The separate existing foundation report records 345 application type errors and 36 failing assertions. Those are not fixed or waived by this change.
- The runtime audit in that run reports three high-severity findings along the braces / micromatch / http-proxy-middleware chain. No forced downgrade or audit suppression is included.

## Changes

1. Replace only the 679 internal tarball URL prefixes with canonical npm registry references. Every package version, dependency edge and integrity hash remains identical. npm treats the canonical registry as the configured registry, so this does not disable the Replit package firewall or change workspace registry settings. Reference: https://docs.npmjs.com/cli/v11/configuring-npm/package-lock-json/ .
2. Run the GitHub checks on Node 22 and verify the locked local Vite, TypeScript, Jest and esbuild executables immediately after installation. A partial install now fails explicitly before a global tool can hide the problem. Replit's production runtime is not changed here.
3. Match the current `pterrified-ui/Door-survey-pro-Plan` field interface's ink / gold / warm-paper palette, compact corners, strong headers and three-step workflow introduction. The reference inspected was its `constants/colors.ts`, `components/Screen.tsx`, home screen and shared controls on 2026-10-18. This is the actual Plan interface, distinct from earlier navy/orange Octo mockups.
4. Retain existing routes, sidebar permissions, billing, accounts, projects, survey protocols, APIs and stored data. No native scanning or measurement processing is copied or advertised as newly implemented. Header, sidebar and dashboard presentation are updated in the existing React application.
5. Correct two small UI defects found during comparison: Dashboard remains highlighted after its redirect to `/dashboard`, and recent-project sorting no longer mutates the shared query-cache array. Correct the existing HSL tap-highlight declaration and honor reduced-motion preferences for entrance animations.
